## 1. 페이지 메타데이터를 우리 서비스 것으로 바꾸기 (필수)

`src/app/layout.tsx:15-18`

브라우저 탭에 뜨는 제목과, 링크를 공유했을 때 보이는 설명을 우리 서비스 것으로
바꾸는 작업입니다. 지금은 "Create Next App"이라 남의 프로젝트처럼 보입니다.

**Before**
```tsx
export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};
```

**After**
```tsx
export const metadata: Metadata = {
  title: "facet",                                  // 최종 서비스명으로
  description: "여기에 한 줄 서비스 소개를 적어주세요",   // 예: "당신의 취향을 발견하는 곳"
};
```

> 팁: `package.json`에는 이름이 `project-carat`로 되어 있습니다. 서비스명을
> `facet`으로 갈지 `carat`으로 갈지 정하고, 여기 제목도 그걸로 통일해 두면
> 나중에 헷갈리지 않습니다.

## 2. 화면 언어를 한국어로 알려주기 (필수)

`src/app/layout.tsx:27`

`<html lang="...">`은 "이 페이지는 무슨 언어로 쓰였다"를 브라우저와 스크린 리더에게
알려주는 표시입니다. 한국어 서비스인데 `en`으로 두면, 화면 읽어주는 기능이 영어 발음으로
한국어를 읽으려 해서 어색해집니다. 한 글자만 바꾸면 됩니다.

**Before**
```tsx
<html
  lang="en"
  className={`${geistSans.variable} ${geistMono.variable} h-full antialiased`}
>
```

**After**
```tsx
<html
  lang="ko"
  className={`${geistSans.variable} ${geistMono.variable} h-full antialiased`}
>
```

## 3. 폰트를 하나로 통일하기 (제안)

`src/app/globals.css:22-26` + `src/app/layout.tsx:30`

지금은 두 곳에서 서로 다른 폰트를 말하고 있습니다.

- `layout.tsx`: Geist 폰트를 불러와서 `--font-geist-sans` 변수로 연결해 둠
- `globals.css`: 그런데 `body`에는 `font-family: Arial`로 적혀 있음

그래서 결과적으로 **기본 글꼴은 Arial, `font-sans`를 붙인 곳만 Geist**가 되는, 섞인
상태입니다. 디자이너 입장에선 가장 신경 쓰이는 부분이라 생각합니다. Geist로 통일해 봅시다.

### 1단계 — globals.css에서 Arial 줄 지우기

**Before** (`globals.css:22-26`)
```css
body {
  background: var(--background);
  color: var(--foreground);
  font-family: Arial, Helvetica, sans-serif;   /* ← 이 줄을 지웁니다 */
}
```

**After**
```css
body {
  background: var(--background);
  color: var(--foreground);
}
```

### 2단계 — layout.tsx의 body에 폰트 클래스 한 번만 걸기

**Before** (`layout.tsx:30`)
```tsx
<body className="min-h-full flex flex-col">{children}</body>
```

**After**
```tsx
<body className="min-h-full flex flex-col font-sans">{children}</body>
```

이렇게 하면 **모든 화면이 한 번에 Geist 폰트로 통일**됩니다. 앞으로 페이지마다
`font-sans`를 또 붙일 필요도 없습니다. (`font-sans`는 globals.css의 `@theme`에 적힌
`--font-sans: var(--font-geist-sans)` 덕분에 Geist를 가리키게 되어 있습니다.)

## 다음 단계 조언 — 디자인 토큰으로 색 관리하기 (지금 당장은 아닙니다)

이건 본인 화면을 본격적으로 그리기 시작할 때 보면 됩니다. 강점과 가장
잘 맞는 부분이라 미리 일러둡니다.

지금 `page.tsx`를 보면 색이 코드 안에 직접 박혀 있습니다. 예를 들면
`hover:bg-[#383838]`, `border-black/[.08]` 같은 식입니다. 이렇게 하면 같은 색을
여러 군데서 쓸 때 일일이 찾아 고쳐야 하고, 색 하나 바꾸려면 온 코드를 뒤져야 합니다.

대신 **Figma에서 쓰던 색 팔레트를 `globals.css`의 `@theme`에 이름으로 정의**해 두고,
그 이름으로 부르는 방식을 추천합니다. 이미 이 프로젝트엔 이 패턴의 씨앗이 깔려
있습니다. (`--color-background`, `--color-foreground`가 그것입니다.)

**globals.css** — 내 색을 등록 (`@theme inline { ... }` 안에 추가)
```css
@theme inline {
  --color-background: var(--background);
  --color-foreground: var(--foreground);
  --font-sans: var(--font-geist-sans);
  --font-mono: var(--font-geist-mono);

  /* 여기에 Figma 팔레트를 옮겨 적습니다 */
  --color-primary: #5b21b6;     /* 예시 — Figma의 메인 색 */
  --color-muted:   #71717a;     /* 예시 — 보조 텍스트 색 */
}
```

**컴포넌트에서 사용** — 등록한 이름으로 호출
```tsx
{/* Before: 색을 직접 박음 */}
<button className="bg-[#5b21b6] text-white hover:bg-[#4c1d95]">버튼</button>

{/* After: 이름으로 부름 → 나중에 globals.css 한 곳만 고치면 전부 반영 */}
<button className="bg-primary text-white hover:opacity-90">버튼</button>
```

이렇게 해두면 "메인 색을 보라색에서 파란색으로 바꿔주세요" 같은 요청이 와도
`globals.css`의 한 줄만 고치면 끝납니다. Figma의 색 변수(Variables)를 코드로 그대로
옮겨오는 셈이라, 디자이너 출신에게는 오히려 더 자연스러운 워크플로라 생각합니다.
