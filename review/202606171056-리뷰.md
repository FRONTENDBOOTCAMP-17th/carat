## 2. [필수] 시즌 배너 이미지가 34MB입니다 — 최적화 필요

`public/images/SeasonalBanner.png`가 **34MB**입니다. 웹 배너 한 장치고는 너무 큽니다(보통 100~300KB면 충분합니다). 문제는 두 가지입니다.

1. **사용자 로딩**: 배너 한 장에 34MB를 받으면 느린 네트워크에선 페이지가 한참 비어 보입니다. 디자인은 공들여 올렸는데 첫인상에서 느리게 뜨면 아깝습니다.
2. **저장소 비대화**: 34MB 바이너리가 git 히스토리에 박히면 이후 clone·pull이 매번 무거워집니다. 한번 커밋된 대용량은 히스토리에 계속 남습니다.

해결법은 가이드 1번에 적었습니다. 요지는 **적정 해상도로 리사이즈 + WebP/최적화 JPEG로 변환**입니다. 디자이너시니 화질 손실 없이 용량 줄이는 감각은 오히려 강점이라 생각합니다. 화면에 필요한 폭(예: 1920px)만큼만 내보내면 화질은 그대로 두고 용량은 수십 분의 일로 줄어듭니다. `[필수]`로 둡니다.

작은 것 하나 더. 콘솔에 이런 경고가 뜹니다(Next 16 변경점):
```
Image ... is using quality "85" which is not configured in images.qualities [75].
Please update your config to [75, 85].
```
`next.config.ts`에 `images: { qualities: [75, 85] }`를 넣으면 사라집니다. `[사소]`

## 3. 응집도·결합도 / React·Next·TS (가능한 선에서)

이번 커밋이 Navbar(50줄)·Collections(38줄)·CollectionCard 등 **컴포넌트 레이아웃 구조도 정리**했는데, 방향이 좋습니다.

**잘한 점**
- `Collections.tsx`가 38줄에서 많이 줄었습니다. 반복되던 카드 묶음을 정리하면서 군더더기를 덜어낸 걸로 보입니다. 응집도를 높이는 좋은 리팩토링입니다.
- `CollectionCard`에서 불필요한 줄을 덜어낸 것도 같은 맥락입니다.
- 배너에 `next/image`를 쓴 것(자동 최적화·lazy)도 방향은 맞습니다. 다만 원본이 34MB면 최적화에도 한계가 있으니, 2장에서 말한 대로 원본부터 줄여야 합니다.

**[제안] Navbar의 위치 (6차에 이어)**
Navbar가 서브페이지 3곳에만 import돼 있고 홈(`/`)엔 없습니다. 같은 내비게이션을 페이지마다 따로 붙이면 메뉴 하나 바뀔 때 여러 파일을 고쳐야 합니다(결합). 모든 페이지에 공통으로 보일 거라면 `app/layout.tsx`에 한 번만 두는 편이 낫습니다. 홈에는 히어로 몰입을 위해 일부러 뺀 거라면 그것도 의도로 존중합니다. 어느 쪽인지만 정해두면 됩니다.
