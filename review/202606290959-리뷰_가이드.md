## 1. 미사용 `import Link` 제거 (1분, 두 파일)

`src/app/contact/page.tsx`와 `src/app/process/page.tsx` 두 곳에서 아래 줄을 지우면 됩니다.

```tsx
import Link from "next/link";   // ← 이 줄 삭제 (JSX에서 <Link>를 안 씀)
```

지우기 전에 정말 안 쓰는지 확인하고 싶으면 터미널에서 이렇게 확인할 수 있습니다.

```bash
grep -n "<Link" src/app/contact/page.tsx src/app/process/page.tsx
# 아무것도 안 나오면 import를 지워도 안전합니다.
```

`npx eslint .`를 돌리면 `'Link' is defined but never used` 경고로도 잡힙니다. 미사용 import는 빌드를 깨지는 않지만, 쌓이면 "이게 진짜 쓰이나?" 헷갈리게 만들어서 그때그때 치워두는 게 좋습니다.

## 2. CustomCursor — Firefox 제외 이유 한 줄 주석

`src/components/CustomCursor.tsx:21~23`이 지금 이렇게 되어 있습니다.

```tsx
const isFirefox = navigator.userAgent.includes("Firefox");
const isPointerFine = window.matchMedia("(pointer: fine)").matches;
if (isFirefox || !isPointerFine) return;
```

여기에 왜 Firefox를 막는지 한 줄만 남겨두면, 나중에 본인이 봐도 의도가 바로 읽힙니다.

```tsx
// Firefox는 커스텀 커서 합성 시 깜빡임/지연이 있어 기본 커서를 그대로 둔다
const isFirefox = navigator.userAgent.includes("Firefox");
// 마우스(정밀 포인터)가 아닌 터치 환경에선 커스텀 커서가 의미 없음
const isPointerFine = window.matchMedia("(pointer: fine)").matches;
if (isFirefox || !isPointerFine) return;
```

(실제로 막은 이유를 본인 말로 적으면 됩니다. 위 문구는 예시입니다.)

## 3. layout 메타데이터 두 줄 보태기

`src/app/layout.tsx:79~82`의 `metadata`를 이렇게 바꿉니다.

```tsx
export const metadata: Metadata = {
  metadataBase: new URL("https://prisme.co"), // 실제 배포 도메인으로
  title: {
    default: "PRISME",
    template: "%s | PRISME",
  },
  description: "Jewelry editorial experience",
};
```

- `metadataBase`: 배포 주소를 한 번 정해두면 OG 이미지 등 상대경로가 절대경로로 자동 보정됩니다. 아직 도메인이 안 정해졌으면 임시값을 넣고 나중에 바꾸면 됩니다.
- `title.template`: 지금은 모든 페이지 제목이 그냥 "PRISME"인데, 하위 페이지가 자기 제목(`title: "Collections"`)을 주면 자동으로 `Collections | PRISME`로 붙습니다. 지금 당장은 효과가 안 보여도, 아래 4번을 하면 살아납니다.

## 4. (선택) collections·fw-collections 공통 컴포넌트로 묶기

두 페이지가 카테고리 키·번역 키·aria id만 다르고 구조가 같습니다. 공통 컴포넌트 하나로 묶으면 한 곳만 고쳐도 둘 다 반영됩니다.

```tsx
// src/components/CategoryCollectionPage.tsx
"use client";

import PageShell from "@/components/PageShell";
import ProductCard from "@/components/ProductCard";
import BackButton from "@/components/BackButton";
import { getProductsByCategory } from "@/lib/products";
import { useLang } from "@/context/LanguageContext";
import type { CategoryKey } from "@/lib/products";

export default function CategoryCollectionPage({
  category,
  pageKey,
}: {
  category: CategoryKey;
  pageKey: "collections" | "fwCollections";
}) {
  const { lang, t } = useLang();
  const products = getProductsByCategory(category, lang);
  const p = t.pages[pageKey];
  const headingId = `${category}-heading`;

  return (
    <PageShell>
      <section className="flex-1 w-full" aria-labelledby={headingId}>
        {/* 기존 collections/page.tsx의 마크업을 그대로, id={headingId}로만 바꿔 옮긴다 */}
      </section>
    </PageShell>
  );
}
```

그러면 두 페이지는 이렇게 얇아집니다.

```tsx
// src/app/collections/page.tsx
import CategoryCollectionPage from "@/components/CategoryCollectionPage";
export default function CollectionsPage() {
  return <CategoryCollectionPage category="collections" pageKey="collections" />;
}
```

```tsx
// src/app/fw-collections/page.tsx
import CategoryCollectionPage from "@/components/CategoryCollectionPage";
export default function FwCollectionsPage() {
  return <CategoryCollectionPage category="fw-collections" pageKey="fwCollections" />;
}
```

PageShell로 껍데기를 묶은 것과 같은 결의 작업이라, 한 번 해보면 "반복을 한 곳으로 모은다"는 감각이 손에 익습니다. 새 카테고리가 늘어날 때 특히 편해집니다.

## 5. (선택) 공개 페이지를 서버 컴포넌트로 — 페이지별 제목

지금 `collections`/`fw-collections`/`products/[id]`가 전부 `'use client'`라 페이지마다 `metadata`를 줄 수가 없습니다(`'use client'` 파일에서는 `metadata` export가 무시됨). 페이지별 제목을 제대로 주려면 페이지 본체는 서버 컴포넌트로 두고, `useLang`을 쓰는 부분만 클라이언트 자식으로 떼어내는 구조가 정석입니다.

```tsx
// src/app/products/[id]/page.tsx  ← 서버 컴포넌트('use client' 없음)
import type { Metadata } from "next";

export async function generateMetadata(
  { params }: { params: Promise<{ id: string }> }
): Promise<Metadata> {
  const { id } = await params;
  const product = getProductById(id);          // 정적 데이터라 서버에서 바로 읽힘
  return { title: product?.name ?? "Product" }; // → "다이아몬드 링 | PRISME"
}

export default async function ProductPage({ params }: { params: Promise<{ id: string }> }) {
  const { id } = await params;
  return <ProductDetailClient id={id} />;        // 상호작용·useLang은 이 자식 안으로
}
```

이건 이번에 꼭 할 일은 아닙니다. 데이터가 정적이라 SEO 손해가 크지 않으니, 다른 마무리를 다 한 뒤 여유가 있으면 한 페이지만 시범으로 바꿔보는 정도로 충분합니다. SEO의 큰 그림(왜 서버 렌더가 검색에 유리한지)은 같이 공유한 `seo-가이드.md`에 정리해 뒀으니 가볍게 훑어보면 됩니다.
