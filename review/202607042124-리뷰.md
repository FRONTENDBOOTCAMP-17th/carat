# carat(PRISME) 18차 코드 리뷰 — 취업 레포 관점 (2026-07-04)

한 줄로 먼저 정리하면, 코드 자체는 걱정할 게 거의 없는 상태입니다. `tsc --noEmit` 0건과 빌드 성공이 이번까지 여러 회차째 그대로 유지되고 있고, 회차를 거치며 쌓인 접근성 디테일(Breadcrumb의 시맨틱 마크업, contact 폼의 aria 속성, CustomCursor의 reduced-motion 분기)에서 디자이너 출신다운 감각이 잘 드러납니다. 다만 이 프로젝트가 주얼리 브랜드를 표방하며 "보는 경험"을 설계 목표로 삼았다는 점을 생각하면, 정작 README나 레포 어디에도 그 화면을 보여주는 스크린샷 한 장, GIF 하나, 데모 링크 하나가 없다는 게 가장 크게 걸립니다. 취업 레포로 공개될 걸 감안하면 지금 남은 시간은 코드를 더 얹기보다 이걸 채우는 데 쓰는 게 맞다고 봅니다.

## 1. 지난 리뷰 반영 현황 — 신규 개발 없음, 유지 확인

17차(7/2) 리뷰 이후 `main`에 새 커밋이 없습니다(HEAD가 그때 머지된 상태 그대로입니다). 혼자 작업하며 조기 수료를 앞둔 일정을 생각하면 새 기능을 더 벌이기보다 지금 화면을 마감 품질로 다듬는 쪽이 자연스러워 보이고, 이번 회차는 그간 지적한 사항들이 잘 유지되고 있는지 다시 짚어봤습니다.

- 12차에서 잡았던 모바일 390px 가로 오버플로(`/collections`, `/fw-collections`의 긴 h1이 컨테이너를 넘치던 문제)는 여전히 잘 닫혀 있습니다. `src/components/CollectionsPage.tsx:30`의 `min-w-0 ... truncate`와 `:35`의 `shrink-0`이 그대로 남아 있고, 두 페이지가 이 컴포넌트 하나를 공유하는 구조라 회귀할 여지도 적습니다.
- 14차에서 권했던 `next.config.ts`의 `images.qualities` 설정도 `[75, 85]`로 반영된 채 유지되고 있습니다.
- 그 외 이전 회차 [제안]·[사소] 항목들도 코드에 그대로 남아 있어, 별도로 다시 지적할 미해결 [필수]는 없습니다.

## 2. 취업 레포로 공개하기 전에 먼저 할 것

다섯 조 공통으로 드리는 조언은 같은 폴더의 [취업레포-가이드.md](./202607042124-취업레포-가이드.md)에 정리해 뒀고, 여기서는 carat 프로젝트에만 해당하는 부분 위주로 짚겠습니다.

**[제안] 배포는 지금 당장 해도 됩니다.** 위시리스트와 로그인이 `localStorage` 기반이고 검색도 `products.json`을 읽는 구조라, 이 프로젝트는 백엔드 의존이 사실상 0입니다. 즉 Vercel에 올렸을 때 환경변수 때문에 깨질 일이 없다는 뜻이고, 배포 리스크가 다른 조보다 훨씬 낮습니다. README 최상단에 데모 링크만 걸어도 인상이 확 달라질 텐데, 지금 README 어디에도 그게 없습니다. 히어로의 3D 인터랙션처럼 움직임 자체가 매력인 부분은 정지 이미지보다 짧은 GIF로 보여주는 편이 훨씬 잘 전달되고, 반응형을 신경 써서 만든 프로젝트인 만큼 데스크톱·모바일 비교 스크린샷도 같이 넣으면 좋겠습니다.

**[제안] `npx eslint .`를 돌리면 8개 에러가 나옵니다.** 전부 `react-hooks/set-state-in-effect` 규칙 하나에 걸리는 것들입니다.

- `src/components/LoginModal.tsx:69`
- `src/components/Navbar.tsx:22`
- `src/components/SearchModal.tsx:27`, `:32`
- `src/context/LanguageContext.tsx:34`
- `src/context/ThemeContext.tsx:29`

전부 마운트 시점에 `localStorage`에 저장된 값을 읽어와 state에 반영하는 자리라, 서버 렌더와 클라이언트 렌더가 어긋나는 hydration mismatch를 피하려는 의도로 짠 코드입니다. 실제로 `tsc`도 `build`도 문제없이 통과하고 동작도 정상이라 지금 당장 급한 버그는 아닙니다. 다만 채용담당자나 다른 개발자가 레포를 열어 lint를 한 번 돌려보면 빨간 줄 8개가 그대로 보이니, "왜 이렇게 짰는지"가 코드에서 드러나도록 손봐두면 인상이 달라집니다. 가이드 문서에 구체적인 방법을 적어뒀습니다.

**[제안] LICENSE 파일이 없고, 카드 클릭 영역이 실제 링크가 아닙니다.** `src/components/ProductCard.tsx:33-36`과 `src/components/CollectionCard.tsx:30-33`을 보면 카드 전체를 `<article role="link" tabIndex={0} onClick={...} onKeyDown={...}>`로 감싸 클릭과 Enter 키로 이동하게 만들어 뒀는데, 동작은 잘 됩니다. 다만 이건 진짜 `<a>` 태그가 아니라서 가운데 클릭이나 우클릭으로 새 탭 열기가 안 되고, 검색엔진 크롤러 입장에서도 실제 링크로 인식되지 않습니다. `<Link>`로 카드 전체를 감싸고 하트 버튼에만 `stopPropagation`을 주는 구조로 바꾸면 이 부분이 자연스럽게 해결됩니다. LICENSE는 강제되는 건 아니지만, MIT 하나만 추가해도 "정리된 레포"라는 인상을 줍니다.

## 3. 대표 구현물 — 이력서에 옮겨 써도 될 만한 것들

지금까지 회차를 거치며 쌓인 구현 중, 취업 레포에서 특히 어필이 될 만한 것들을 모아봤습니다. 어느 하나가 갑자기 나온 게 아니라 회차마다 하나씩 다듬어온 결과라, 각각을 "왜 이렇게 만들었는지" 한 문장씩 설명할 수 있으면 면접에서도 좋은 재료가 됩니다.

- **`PageShell.tsx`(14차 리팩터링)** — Navbar·main·Footer를 감싸는 12줄짜리 껍데기 컴포넌트 하나로 14개 페이지에 흩어져 있던 168줄의 반복 코드를 제거했습니다. 단순히 "코드를 줄였다"가 아니라, 서버 컴포넌트인 `PageShell`과 클라이언트 컴포넌트인 `Navbar`를 정확히 분리해서 가져간 부분이 눈에 띕니다.
- **`Breadcrumb.tsx`** — `<nav aria-label="Breadcrumb">`(:11) 안에 `<ol>`(:12)을 쓰고 마지막 항목에만 `aria-current="page"`(:32)를 붙인 구조가 WCAG 내비게이션 패턴을 정확히 따르고 있습니다. 데스크톱과 모바일에서 Breadcrumb과 BackButton을 다르게 노출하는 분기도 함께 잘 짜여 있습니다.
- **`CustomCursor.tsx`** — 커스텀 커서라는, 자칫 접근성을 해치기 쉬운 인터랙션을 만들면서도 Firefox의 휠 오토스크롤과 충돌하는 문제를 발견해 제외 처리했고(:21-25, 이유도 주석으로 남겨뒀습니다), 터치·펜 디바이스도 함께 제외했습니다. `prefers-reduced-motion`을 감지해 보간 애니메이션 대신 즉시 점프하도록 분기하고, `useEffect` 클린업(:156-164)에서 `requestAnimationFrame` 두 개와 리스너 네 개를 빠짐없이 해제해 메모리 누수 없이 정리한 것도 눈여겨볼 만합니다.
- **`Hero.tsx`** — react-three-fiber로 스크롤에 반응하는 3D 히어로를 구현하면서, WebGL을 지원하지 않는 환경을 위한 정적 이미지 fallback(:239-247)까지 마련해 뒀습니다. 화려한 인터랙션만 만든 게 아니라 안 되는 환경까지 고려한 것이라, 구현 난이도와 함께 좋은 어필거리입니다.
- **`SearchModal.tsx`** — `role="combobox"`(:114)와 `role="listbox"`(:133)/`role="option"`(:141), `aria-activedescendant`(:117)까지 갖춰 화살표 키로 옵션을 옮기고 Enter로 이동하는 검색 UI를 직접 구현했습니다. 흔히 라이브러리에 의존하는 콤보박스 패턴을 손으로 짜본 경험이라 기술 면접에서 설명하기 좋은 소재입니다.
- **`products/[id]/page.tsx` 서버 컴포넌트 전환** — 처음엔 클라이언트 컴포넌트로 시작했던 상세 페이지를 서버 컴포넌트로 옮기고 `generateMetadata`로 상품별 `<title>`을 만들어내도록 바꿨습니다(:21-30). 왜 클라이언트 컴포넌트로는 페이지별 메타데이터가 안 되는지, 그래서 어떤 구조로 옮겼는지까지 설명할 수 있으면 Next.js 이해도가 그대로 드러납니다.
- **`CollectionsPage.tsx` 공통화** — `/collections`와 `/fw-collections`가 카테고리 하나만 다르고 나머지 마크업이 완전히 같았던 걸 컴포넌트 하나로 묶어냈습니다. 중복을 찾아내 인자로 뽑아내고 걷어냈다는, 흔하지만 실제로 해본 사람만 이야기할 수 있는 리팩토링 사례입니다.

## 4. 위생·마크업·접근성

`console.log`나 `TODO`, 하드코딩된 키 같은 잡음은 눈에 띄지 않고 전반적으로 깔끔합니다. 몇 가지만 짚어두겠습니다.

- **[칭찬]** `src/app/contact/page.tsx`의 폼이 인상적입니다. name·email·message 세 필드 전부에 `aria-invalid`(:145, :169, :192)와 에러가 있을 때만 걸리는 `aria-describedby`(:146, :170, :193)를 붙였고, 에러 메시지에는 `role="alert"`(:149, :173, :196)를 달아 스크린리더가 즉시 읽도록 했습니다. `noValidate`로 브라우저 기본 검증을 끄고 직접 검증 로직을 짠 것도 의도가 분명해 보입니다.
- **[칭찬]** `PageShell.tsx:6`의 `<main id="main-content">`가 SkipLink의 이동 대상 역할을 전역적으로 해주고 있어서, 페이지마다 따로 챙길 필요가 없는 구조입니다.
- **이미지 최적화**: `public/images/SeasonalBanner.webp`가 약 1.8MB인데, 과거 34MB였던 원본을 WebP로 바꿔 대폭 줄인 결과라 방향은 맞습니다. 지금 크기도 배포에 문제 될 수준은 아닙니다.
- **[사소]** `Hero.tsx:240-246`의 WebGL 미지원 fallback이 `/images/ring-hero.webp`를 가리키는데, 실제로 이 파일이 없습니다(`public/images/`에는 `SeasonalBanner.webp`만 있습니다). 다행히 바로 위 줄(:240)에 본인이 "정지 이미지로 교체할 것"이라는 주석을 이미 남겨둬서 인지하고 있는 듯하고, WebGL을 지원하지 않는 환경 자체가 적어 마감 전 급하게 처리할 항목은 아닙니다.
- 제품 이미지가 아직 없어 카드마다 회색 placeholder(`role="img"` + `aria-label`)로 대체돼 있는 것은, 디자인 단계에서 실제 상품 촬영본이 없는 상황을 감안하면 합리적인 임시 처리로 보입니다. 데모 캡처를 찍기 전에 이 부분만 실제 이미지 몇 장으로 채워도 화면이 훨씬 완성돼 보일 겁니다.

정적 검증 결과도 함께 남겨둡니다.

- `tsc --noEmit` — 0건.
- `npm run build` — 18개 라우트 전부 성공(Turbopack, 2.6초).
- `npx eslint .` — 8 error, 4 warning. 에러 8건은 위 2번에서 다룬 `set-state-in-effect` 건들이고, 경고 4건 중 1건(`carat-daily.spec.ts`의 미사용 변수)은 리뷰용 테스트 스펙 파일이라 학생 코드와 무관합니다. 나머지 3건은 `CustomCursor.tsx`의 미사용 변수 하나, `Hero.tsx`의 `<img>` 사용 권고(위 fallback 부분), `LanguageContext.tsx`의 `exhaustive-deps` 경고로, 전부 마감을 미룰 만한 수준은 아닙니다.

## 5. E2E — 이번 회차는 라이브 재실행을 생략합니다

이번 회차는 실제 브라우저를 띄운 라이브 E2E를 새로 돌리지 않았습니다. 17차(7/2) 리뷰 이후 `main`에 코드 변경이 전혀 없어서 화면 동작이 그때와 달라졌을 가능성이 없고, 오늘 점검의 초점도 기능 검증보다는 취업 레포로서의 완성도를 보는 데 있었기 때문입니다. 가장 최근 실측은 `review/images/2026-07-02/`에 남아 있는 캡처이고, 그때 확인한 내용은 다음과 같습니다.

- 홈·목록·상세 화면이 데스크톱·모바일 모두 정상 렌더.
- 상세 페이지 `<title>`이 상품별로 다르게 나오는 것 확인(`generateMetadata` 정상 동작).
- 검색 모달 키보드 네비게이션(화살표 이동, Enter 이동) 정상.
- 9개 시나리오 중 8개 통과, 실패한 1건은 리뷰 테스트 쪽 셀렉터 문제로 실제 화면 문제는 아니었습니다.

코드가 그대로인 만큼 이 결과는 오늘도 유효하다고 보되, 다음 회차에서 README에 데모 링크나 스크린샷을 추가하는 등 실제 변경이 생기면 그때 다시 라이브로 확인하겠습니다.

---

전체적으로 코드 품질은 이미 마감해도 될 수준입니다. 남은 시간은 기능을 더 얹기보다, 이 프로젝트가 가진 걸 처음 보는 사람에게 어떻게 보여줄지에 쓰는 게 맞다고 봅니다. 화이팅입니다.
