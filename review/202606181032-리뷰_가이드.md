## 1. 배너 이미지 최적화 [필수·이월]

`public/images/SeasonalBanner.png`가 34MB입니다. 배너 한 장 치고는 지나치게 커서 첫 로딩이 느려지고, git에도 그대로 쌓이게 됩니다.
가로 폭을 실제 표시 크기에 맞춰 줄이고 WebP로 바꾸면, 화질은 거의 그대로 둔 채 용량만 크게 덜어낼 수 있습니다.

### 방법 A — 명령줄(가장 빠름)

`sharp-cli`나 `cwebp`면 한 줄로 끝납니다.

```bash
# sharp-cli (npx로 설치 없이)
npx sharp-cli -i public/images/SeasonalBanner.png -o public/images/SeasonalBanner.webp resize 1920 --withoutEnlargement -f webp -q 80

# 또는 cwebp (webp 도구)
cwebp -q 80 -resize 1920 0 public/images/SeasonalBanner.png -o public/images/SeasonalBanner.webp
```

보통 34MB가 수백 KB까지 떨어집니다. 그다음엔 컴포넌트에서 경로만 `.webp`로 바꿔주면 끝입니다.

```tsx
// SeasonalBanner.tsx
<Image src="/images/SeasonalBanner.webp" alt="F/W 2026 컬렉션 배너" ... />
```

### 방법 B — 도구 없이

Figma나 미리보기(Preview)에서 가로 1920px 내외로 내보낸 뒤, [squoosh.app](https://squoosh.app) 같은 웹 도구에 올려 WebP·품질 80으로 내려받아도 똑같습니다.

> 참고: git 히스토리에 이미 34MB가 커밋돼 있다면, 파일을 교체해도 과거 커밋의 용량은 그대로 남습니다.
> 지금 단계에서 거기까지 손볼 필요는 없습니다. 앞으로 큰 원본을 커밋하지 않는 것 정도만 신경 써주세요.

## 3. (참고) 인증 백엔드 연결 시

지금 `AuthContext`의 `login`/`logout` 인터페이스는 잘 잡혀 있습니다. 나중에 실제 백엔드를 붙일 때는
이 인터페이스는 그대로 두고 안쪽 구현만 갈아끼우면 됩니다. 가령 `login`이 지금은 `localStorage`에 쓰고 있는데,

```ts
// 지금(요지): localStorage 저장
const login = async (email, password) => {
  localStorage.setItem("prisme_user", JSON.stringify({ email, ... }));
  return { error: null };
};

// 나중: 내부만 교체 — 화면 코드는 그대로
const login = async (email, password) => {
  const { error } = await supabase.auth.signInWithPassword({ email, password });
  return { error: error?.message ?? null };
};
```

이렇게 인터페이스만 유지해 두면 화면 쪽 코드는 한 줄도 건드릴 일이 없습니다. 당장 할 일은 아니니, 방향만 머리 한쪽에 담아두면 충분합니다.
