## 3. 코드 리뷰 — 접근성·구조

### 칭찬할 점

- **contact/page.tsx 폼 접근성이 정말 탄탄합니다.** 전 필드에 `aria-invalid`+`aria-describedby`를 일관되게 걸었고(`145-146`, `169-170`, `192-193`), 오류 메시지에 `role="alert"`를 붙여(`149` 등) 스크린리더가 즉시 읽도록 했습니다. `noValidate`로 브라우저 기본 검증을 끄고 직접 검증을 돌리는 흐름, `autoComplete` 지정, 연락처 정보를 `<dl>/<dt>/<dd>`로 시맨틱하게 묶은 부분(`90-103`)까지 — 1인 프로젝트에서 이 정도 완성도는 드뭅니다.
- **CustomCursor.tsx의 모션 처리도 깔끔합니다.** animate 루프(`132-148`)에서 `prefers-reduced-motion`을 즉시 분기해 보간 없이 점프하도록 했고, cleanup(`156-164`)에서 RAF와 리스너를 빠짐없이 정리합니다. `has-custom-cursor` 클래스로 `cursor:none`을 조건부로만 적용하는 것도 안전합니다.

### 짚어둘 점

- **[제안] collections / fw-collections 페이지가 1~57줄이 사실상 동일합니다.** `src/app/collections/page.tsx`와 `src/app/fw-collections/page.tsx`를 비교해보면 함수 이름, `getProductsByCategory`의 카테고리 키, `t.pages` 번역 키, `aria-labelledby` id 네 곳만 다르고 나머지는 같습니다. 지금 당장 버그가 나는 건 아니지만, 한쪽을 고치면 다른 쪽도 똑같이 고쳐야 하는 구조라 유지보수 비용이 두 배가 됩니다. `CollectionListPage({ category, pageKey, headingId })` 같은 공통 컴포넌트로 추출하면 한 곳만 고쳐도 두 페이지가 같이 따라옵니다. 해결법은 가이드에 예시 코드로 적어뒀습니다.
- **[사소] contact의 "새 문의" 버튼에 `type`이 빠져 있습니다.** `src/app/contact/page.tsx:117`의 `<button>`에 `type`이 지정돼 있지 않은데, HTML에서 폼 안의 버튼은 기본값이 `submit`입니다. 지금은 폼 바깥 분기(제출 성공 화면)에 있어서 실제로 폼을 다시 제출하진 않지만, 의도가 "초기화"인 만큼 `type="button"`을 명시해두면 더 안전하고 의도도 분명해집니다.
- **[사소] process/page.tsx:42의 `lang` 속성을 한 번 점검해보면 좋겠습니다.** 단계 부제목을 `<p lang={lang === "ko" ? "en" : "ko"}>`로 출력하는데, `s.sub`이 항상 영문이라면 지금은 문제없습니다. 다만 나중에 번역을 추가해서 `s.sub`이 현재 언어와 같아지면 `lang` 속성이 실제 내용과 어긋나 스크린리더가 잘못된 언어로 읽을 수 있으니, 그때 한 번 다시 봐주면 됩니다.
