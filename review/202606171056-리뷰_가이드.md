## 1. [필수] 시즌 배너 34MB 최적화

웹 배너 한 장이 34MB면 너무 큽니다. 화면에 필요한 폭만큼 줄이고 WebP(또는 최적화 JPEG)로 바꾸면 화질은 거의 그대로인데 용량은 수십 분의 일로 떨어집니다.

### 변환 (둘 중 편한 쪽)

**Figma/디자인 툴에서**: 배너가 실제로 깔리는 최대 폭(보통 1920px, 레티나까지 보면 2560px)으로 export 합니다. PNG 말고 **WebP**로, 안 되면 품질 80 JPEG로. 사진이라 PNG로 둘 이유가 없습니다. PNG는 로고나 투명도가 필요할 때 씁니다.

**CLI(squoosh/sharp/ImageMagick)**:
```bash
# ImageMagick 예: 폭 1920, 품질 82 webp
magick SeasonalBanner.png -resize 1920x -quality 82 SeasonalBanner.webp
# 또는 sharp-cli
npx sharp -i SeasonalBanner.png -o SeasonalBanner.webp resize 1920 -- webp --quality 82
```
보통 34MB가 200~400KB 정도로 내려갑니다.

### 코드 교체
```tsx
// SeasonalBanner.tsx — 확장자만 교체
<Image src="/images/SeasonalBanner.webp" alt="2026 F/W Collections" ... />
```

### git 히스토리 정리(선택)
이미 34MB가 커밋돼서 히스토리에 남아 있습니다. 작은 파일로 교체 커밋만 해도 앞으로 clone 할 때 큰 영향은 없습니다(최신 트리만 받으면 되니까요). 히스토리까지 깔끔히 비우고 싶으면 `git filter-repo`로 그 blob을 지울 수 있습니다. 혼자 쓰는 repo라 부담은 적지만 굳이 안 해도 됩니다. **새 작은 이미지로 갈아끼우는 것만으로 충분**합니다.

## 2. [사소] next.config 이미지 품질 설정

Next 16부터는 `next/image`의 `quality` 값을 config에 선언해야 경고가 안 뜹니다.
```ts
// next.config.ts
const nextConfig: NextConfig = {
  images: {
    qualities: [75, 85],
  },
};
export default nextConfig;
```

## 3. [제안] Navbar 위치

모든 페이지에 공통으로 보일 거라면 `app/layout.tsx`에 한 번만 두면 됩니다.
```tsx
// app/layout.tsx
import Navbar from "@/components/Navbar";

export default function RootLayout({ children }) {
  return (
    <html lang="ko">
      <body>
        <Navbar />        {/* 한 곳에서 관리 → 메뉴 변경 시 1파일만 수정 */}
        {children}
      </body>
    </html>
  );
}
```
홈은 히어로 몰입을 위해 일부러 뺀 거라면, 그 의도를 주석 한 줄로 남겨두면 다음에 볼 때 헷갈리지 않습니다.
