# carat(facet) 중복 코드 리뷰 (2026-06-25)

이번엔 **반복·복붙된 코드**를 한 번 훑었습니다. 같이 드린 「리팩토링 가이드」가 원칙이라면, 이 문서는 그걸 carat 코드에 대입한 결과입니다. 다만 이 프로젝트는 **혼자 UI/시각 구현에 무게를 두고, 일찍 수료하실 예정**이라는 점을 감안해서, 시각 품질을 해치지 않는 선의 가벼운 정리만 골랐습니다. 과한 추상화는 권하지 않습니다.

먼저 칭찬부터. **데이터·로직 중복은 거의 없습니다.** `products.ts`, `motion.ts`, `translations.ts`로 라이브러리화가 잘 돼 있어요. 중복은 전적으로 **"같은 비주얼 템플릿을 페이지·카드마다 마크업째 복붙"** 한 UI 레이어에 몰려 있습니다. 화면은 정교한데, 같은 레이아웃 골격이 아직 공용 컴포넌트로 승격되지 못한 상태라고 보면 됩니다.

## 1. [제안] 컬렉션 목록 페이지 3형제가 거의 100% 동일합니다

`collections / fw-collections / best-pieces` 세 페이지가 변수 ID와 카테고리 키만 다르고 사실상 바이트 단위로 같습니다.

- `app/collections/page.tsx:15-62`
- `app/fw-collections/page.tsx:15-62`
- `app/best-pieces/page.tsx:15-62`

```tsx
<section className="flex-1 w-full" aria-labelledby="collections-heading">
  <div className="max-w-container mx-auto px-4 pt-16 pb-24 sm:px-6 lg:px-8">
    <nav aria-label={p.backNav} className="mb-10"><BackButton href="/" label="PRISME" /></nav>
    <header className="mb-16">
      <p className="mb-6 text-xs tracking-label text-content-faint">{p.section}</p>
      <h1 id="collections-heading" className="...">{p.title}</h1>
    ...
```

Rule of Three가 정확히 맞아떨어지는 교과서 사례입니다(3곳). 카테고리가 늘어날수록 같은 파일을 또 복사하게 되니, 지금 공용 `CategoryListPage` 하나로 빼는 걸 권합니다. 카테고리 키만 props로 받고 `id`는 `${category}-heading`로 생성하면 됩니다.

```tsx
// 세 page.tsx는 이렇게 얇아집니다
export default function CollectionsPage() {
  const { lang, t } = useLang();
  return <CategoryListPage category="collections" p={t.pages.collections} lang={lang} />;
}
```

## 2. [제안] 정적 콘텐츠 페이지 7개가 같은 스캐폴드를 반복합니다

`materials / care-guide / shipping / process / archive / faq / contact` 일곱 페이지가 `← PRISME` 백 링크 + `section/h1/desc` 헤더를 거의 글자 그대로 복붙합니다. `min-h-screen bg-surface-darkest flex flex-col` 래퍼는 15곳에 반복돼요.

여기서 주의 — **페이지 전체를 추상화하지 마세요.** 각 페이지 본문은 다 다르니까요. 공통인 **껍데기(`PageShell`)와 헤더(`PageHeader`)만** 빼고, 본문은 children으로 받아 페이지마다 자유롭게 두는 게 시각 품질을 지키면서 정리하는 길입니다.

```tsx
<PageShell labelledBy="materials-heading">
  <PageHeader section={p.section} title={p.title} desc={p.desc} />
  {/* 본문은 페이지마다 자유롭게 */}
</PageShell>
```

참고로 백 링크가 어떤 페이지는 `<BackButton>`, 어떤 페이지는 raw `<Link href="/">← PRISME`로 컨벤션이 갈려 있습니다. `BackButton`이 history 처리까지 해주니 그쪽으로 통일하면서 `PageShell`에 흡수시키면 자연히 해결됩니다.

## 3. [제안] 하트(위시리스트) 버튼이 클래스·a11y·가드까지 복붙됐습니다

`ProductCard`와 `CollectionCard`의 하트 버튼이 클래스 문자열까지 동일하고, 위시리스트 가드도 같습니다.

- `ProductCard.tsx:40-51` / `CollectionCard.tsx:37-48`
- 가드 `if (!user) { openLoginModal("login"); return; }`가 `WishlistButton.tsx:13`, `CollectionCard.tsx:22`, `ProductCard.tsx:25` 세 곳에

```tsx
<button onClick={handleWishlist}
  className={`absolute top-2 right-2 size-11 ... ${inWishlist ? "opacity-100 ..." : "opacity-0 group-hover:opacity-100 ..."}`}
  aria-label={inWishlist ? t.productCard.removeFromWishlist : t.productCard.addToWishlist}
  aria-pressed={inWishlist}>
  <Heart size={18} fill={inWishlist ? "currentColor" : "none"} aria-hidden="true" />
</button>
```

UI 중복은 단순히 보기 흉한 게 아니라, **`aria-pressed`·`aria-label` 같은 접근성 속성을 한쪽만 고치면 버그가 됩니다.** 하트 버튼은 `HeartToggle` 컴포넌트로, 가드는 `useWishlistToggle` 훅으로 빼면 깔끔합니다.

```tsx
function useWishlistToggle(item) {
  const { user, wishlist, toggleWishlist, openLoginModal } = useAuth();
  const inWishlist = wishlist.some((w) => w.id === item.id);
  const toggle = () => { if (!user) return openLoginModal("login"); toggleWishlist(item); };
  return { inWishlist, toggle };
}
```

(`ProductCard`와 `CollectionCard`는 이미지 비율과 desc 유무만 다르니 장기적으론 한 컴포넌트로 합칠 수도 있지만, 그건 지금 안 하셔도 됩니다.)

## 4. [사소] 가격 매직값이 두 곳으로 갈라져 있습니다

`essential` 페이지의 가격 `₩ 10,000,000`이 `app/essential/page.tsx:32`와 `:143` 두 곳에 따로 박혀 있습니다. 한 곳만 고치면 화면 표시값과 위시리스트 저장값이 어긋나요. 상수 하나로 합쳐 양쪽에서 참조하세요.

```tsx
const PRICE = "₩ 10,000,000";
```

(소재·치수 문자열이 `lib/products.ts:45`에 고정돼 모든 상품이 같은 값을 받는 것도 보이는데, 이건 원래 상품별로 달라야 할 데이터이니 여유 되면 `products.json`으로 옮기는 정도로 두셔도 됩니다.)

## 5. [사소] 반복되는 Tailwind 클래스 — 2·3번 끝나면 거의 사라집니다

긴 클래스 조합이 흩어져 있습니다(링크 스타일 20곳, cinzel 폰트 인라인 `style` 26곳, 컨테이너 16곳 등). 다만 이 중 상당수는 **1~3번 컴포넌트화가 끝나면 자연히 사라집니다.** 남는 것만 가볍게 토큰으로 빼세요. 특히 cinzel 폰트를 인라인 `style={{ fontFamily: ... }}` 대신 Tailwind `font-cinzel` 유틸이나 전역 헤딩 클래스로 묶으면 26곳의 인라인 style이 사라져 체감이 큽니다.

```ts
// styles.ts
export const linkMuted = "text-xs tracking-label text-content-secondary hover:text-content-primary transition-colors";
```

## 한 줄 정리

로직 중복은 거의 없고, 중복은 전부 **같은 비주얼 템플릿을 페이지·카드마다 마크업째 복붙**한 UI 레이어에 있습니다. 1인·시각 우선 프로젝트라는 점을 감안하면, 무리하게 다 합칠 필요는 없고 **① 목록 페이지 3형제(1번) → ② 페이지 껍데기/헤더(2번) → ③ 하트 버튼·가드(3번)** 정도만 빼도 코드가 한결 가벼워집니다. 가격 매직값(4번)은 버그 소지가 있으니 합쳐두시고, 나머지는 여유 될 때 보셔도 됩니다.
