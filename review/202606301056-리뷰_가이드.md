## 1. [제안] collections / fw-collections 공통 컴포넌트 추출

지금 두 페이지는 함수 이름·카테고리 키·번역 키·`aria-labelledby` id만 다르고 본문이 같습니다. 다른 네 가지를 props로 받는 공통 컴포넌트를 하나 만들어두고, 각 페이지는 그걸 호출만 하도록 바꾸면 됩니다.

### 1) 공통 컴포넌트 만들기

`src/components/CollectionListPage.tsx` (이름·위치는 취향대로):

```tsx
"use client";

import PageShell from "@/components/PageShell";
import { useLang } from "@/context/LanguageContext";
import { getProductsByCategory } from "@/lib/products";
// 기존 page.tsx에서 쓰던 카드/그리드 import 그대로 가져옵니다.

type CategoryKey = "collections" | "fw-collections";

export default function CollectionListPage({
  category,
  pageKey,
  headingId,
}: {
  category: CategoryKey;
  pageKey: "collections" | "fwCollections";
  headingId: string;
}) {
  const { t, lang } = useLang();
  const products = getProductsByCategory(category, lang);
  const p = t.pages[pageKey];

  return (
    <PageShell>
      <section className="flex-1 w-full" aria-labelledby={headingId}>
        {/* 기존 page.tsx의 본문(헤더 h1 + 그리드)을 그대로 옮깁니다.
            h1에는 id={headingId} 를 답니다. */}
        <h1 id={headingId} /* ...기존 클래스 그대로... */>
          {p.title}
        </h1>
        {/* products 매핑 그리드도 기존 그대로 */}
      </section>
    </PageShell>
  );
}
```

핵심은 **다른 부분만 props로 빼는 것**입니다. 두 페이지를 비교했을 때 달랐던 네 군데(`getProductsByCategory`의 첫 인자, `t.pages.___`, `aria-labelledby`/`id`)가 전부 `category`·`pageKey`·`headingId`로 들어갔습니다.

### 2) 각 페이지는 호출만

`src/app/collections/page.tsx`:

```tsx
import CollectionListPage from "@/components/CollectionListPage";

export default function CollectionsPage() {
  return (
    <CollectionListPage
      category="collections"
      pageKey="collections"
      headingId="collections-heading"
    />
  );
}
```

`src/app/fw-collections/page.tsx`:

```tsx
import CollectionListPage from "@/components/CollectionListPage";

export default function FwCollectionsPage() {
  return (
    <CollectionListPage
      category="fw-collections"
      pageKey="fwCollections"
      headingId="fw-collections-heading"
    />
  );
}
```

이렇게 해두면 카드 디자인이나 그리드 간격을 바꿀 때 `CollectionListPage` 한 곳만 고쳐도 두 페이지가 같이 따라옵니다. 한쪽만 고치고 다른 쪽을 깜빡하는 실수도 구조적으로 사라지고요.

> 옮긴 뒤에는 `npx tsc --noEmit`로 타입이 맞는지, 화면 두 페이지가 이전과 똑같이 보이는지 한 번씩만 확인하면 됩니다.

## 3. (선택) 페이지별 title이 필요해지면

지금 contact·process가 `'use client'`라 `title.template`이 안 붙는다고 했는데, 페이지 제목을 `Contact | PRISME`처럼 붙이고 싶어지면 **서버 컴포넌트(메타데이터 담당)와 클라이언트 컴포넌트(`useLang` UI)를 분리**하면 됩니다.

```tsx
// src/app/contact/page.tsx  ← 서버 컴포넌트 (use client 제거)
import type { Metadata } from "next";
import ContactView from "./ContactView";   // 'use client' 쪽으로 분리

export const metadata: Metadata = { title: "Contact" }; // → "Contact | PRISME"

export default function ContactPage() {
  return <ContactView />;
}
```

`'use client'`와 `useLang`이 들어간 지금 본문은 `ContactView.tsx`로 그대로 옮기면 됩니다. 다만 당장 필요한 작업은 아니고, SEO를 더 챙기고 싶을 때만 손대면 되는 선택지입니다. 디자인 쇼케이스 단계에서는 지금처럼 둬도 괜찮습니다.
