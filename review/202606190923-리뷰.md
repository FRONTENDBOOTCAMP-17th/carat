# carat(PRISME) 9차 코드 리뷰 (2026-06-19)

다음 주 월요일(6/22) 사용자·관리자 기능 중간 시연을 앞두고, 화면이 실제로 잘 도는지 먼저 확인하고 코드를 봤습니다.
8차(6/18) 이후로는 새 커밋 없이 같은 코드 상태라, 이번 회차는 손볼 게 많지 않습니다. 시연을 앞둔 점검 겸,
지난번 이월한 배너 용량 한 가지를 다시 또렷하게 짚어 두는 자리로 보면 됩니다.

E2E를 데스크톱·모바일 양쪽으로 다시 돌렸고(아래 "E2E 결과"), 시각 구현과 반응형, 그리고 시연 흐름이 끊김 없이
이어지는지를 중심으로 확인했습니다.

## 2. 이번 회차에서 잘된 것

새 코드는 없지만 시연 흐름을 따라가며 다시 보니, 8차까지 쌓아온 화면들이 안정적으로 잘 돌아갑니다. 특히 로그인·회원가입
모달은 디자이너의 강점이 코드로 드러나는 부분이라 한 번 더 짚어 두고 싶네요.

- **로그인/회원가입 모달(`LoginModal.tsx`)**: 시연에서 첫인상을 좌우할 화면인데 완성도가 높습니다. `LOGIN`/`SIGN UP`을 Cinzel로
  잡은 타이포, 비밀번호 표시 토글, 로그인↔회원가입 모드 전환이 모두 매끄럽고, 데스크톱·모바일 모두 가로 오버플로 없이 폭이 잘 맞습니다
  (E2E D8a~D8c).
- **입력 검증 설계**: 필드별 검증을 `validateField` 하나로 모으고, `touched`(blur 후)·`fieldErrors`를 나눠서 "건드린 필드만 에러를 보여주는"
  흐름을 만든 점이 좋습니다. 비밀번호를 바꾸면 비밀번호 확인 필드를 다시 검증하도록 연동해 둔 것도 세심합니다. 폼 UX를 이 정도로 잡아 두면
  시연에서 잘못된 값을 넣어 보여도 자연스럽게 안내가 뜹니다.
- **접근성 디테일**: 모달에 `role="dialog"`/`aria-modal`, 입력마다 `aria-invalid`·`aria-describedby`, 에러 문구에 `role="alert"`,
  비밀번호 토글에 상태별 `aria-label`까지 들어가 있습니다. Navbar의 메뉴/계정 버튼도 `aria-expanded`·`aria-controls`로 상태를 알려 줍니다.
  "보기 좋다"를 넘어 "스크린리더로도 쓸 수 있다"까지 챙긴 부분이라 칭찬하고 싶습니다.
- **반응형 안정성**: 랜딩·리스트 3종·위시리스트 모두 모바일 390에서 가로 오버플로가 0이었습니다(E2E D1~D9). 시연을 휴대폰으로 보여줘도
  레이아웃이 무너지지 않습니다.

정적 검증도 깨끗합니다. `npx tsc --noEmit` 0건, `npm run build` 성공(6개 라우트 `/`·`/best-pieces`·`/collections`·`/fw-collections`·`/wishlist`·`/_not-found` 전부 Static ○)입니다.

## 3. 시연 전에 한 가지만 — 배너 이미지 용량 [필수·이월]

`public/images/SeasonalBanner.png`를 직접 열어 보니 **7952×5304px, 34MB**였습니다. 사진 원본 해상도가 그대로 들어가
있는 상태인데, 이게 시연에서 두 가지로 걸립니다.

하나는 **첫 화면 로딩**입니다. 시연 당일 네트워크가 평소만 못하면 메인에 들어와서 F/W 배너가 뜨기까지 눈에 띄게 버벅일 수 있습니다.
지금은 `priority`로 먼저 불러오게 해 둬서, 오히려 이 무거운 이미지가 초기 로딩을 잡아끄는 모양이 됩니다.

다른 하나는 **저장소 히스토리**입니다. 34MB짜리 파일이 한 번 커밋되면 이후에 지워도 git 히스토리에는 영구히 남기 때문에,
클론이나 체크아웃이 계속 무거워집니다.

배너 용도라면 가로폭을 실제 표시 크기(예: 1920px 내외)로 줄이고 WebP로 바꾸는 것만으로 화질은 거의 그대로 두면서 용량을 수백 KB까지,
지금의 1/50 수준으로 낮출 수 있습니다. `SeasonalBanner.tsx`가 이미 `placeholder="blur"`로 흐릿한 미리보기를 잘 깔아 둔 만큼,
원본만 가볍게 바꿔 끼우면 로딩 체감이 확 좋아집니다. 변환 방법은 가이드에 단계별로 정리해 뒀습니다.

같이 따라오는 [사소]도 하나 있습니다. 배너 `<Image quality={85}>`를 쓰고 있는데 `next.config`에 `images.qualities`가 없어서,
dev로 띄우면 콘솔에 이런 경고가 실제로 뜹니다.

```
Image with src "/_next/static/media/SeasonalBanner...png" is using quality "85"
which is not configured in images.qualities [75]. Please update your config to [75, 85].
```

기능에는 지장이 없지만, 시연 때 콘솔을 열어 보여줄 일이 있으면 거슬리니 배너 정리하면서 같이 넣으면 깔끔합니다(가이드 참고).

## 4. 시연 시나리오에 대한 메모 — "관리자 기능"을 어떻게 말할지

이번 시연 주제가 "사용자·관리자 기능"이라, 미리 한 가지 정리해 두면 좋겠습니다. 지금 PRISME는 브랜드 스토어 프론트를 보여주는
프로젝트라 관리자 화면이 따로 없습니다. 이건 빠진 게 아니라 프로젝트 성격상 자연스러운 선택이라, 시연에서 굳이 없는 기능을 만들어
보여주기보다 **"사용자 여정"을 처음부터 끝까지 매끄럽게 보여주는 쪽**으로 가는 편이 훨씬 강점이 살 거라 생각합니다. 즉 메인 진입 →
컬렉션 둘러보기 → 회원가입/로그인 → 위시리스트 진입(가드 동작) 흐름을 한 번에 이어 보여주는 식입니다. 혹시 시연 요건상 관리자
역할을 꼭 언급해야 한다면, "이 프로젝트는 고객 대면 스토어에 집중했고 운영자 화면은 범위 밖으로 뒀다"고 한 줄 정리해 두면 충분할 듯합니다.

연결해서 [제안] 하나. 지금 로그인은 `localStorage`(`prisme_user`/`prisme_wishlist`) 기반의 클라이언트 전용입니다. 디자인을
보여주는 목적엔 충분하고 적절한 선택이라 생각합니다. 다만 이건 "화면상의 로그인"이지 서버가 검증하는 진짜 인증은 아니라서, 콘솔에서
값을 넣으면 로그인 상태가 됩니다(E2E에서도 이 방식으로 로그인 상태를 재현했습니다). 시연에서 누가 "인증은 어떻게 되나요?"라고 물으면
"지금은 화면 흐름을 보여주는 클라이언트 데모이고, 백엔드는 `AuthContext`의 `login`/`logout` 인터페이스를 그대로 두고 내부만
갈아끼우면 붙는 구조"라고 답하면 깔끔합니다. 실제로 그렇게 잡혀 있어서 나중에 전환도 수월합니다.

## 5. E2E 결과 (2026-06-19)

dev 서버(`PORT=3501`)를 직접 띄워 데스크톱·모바일을 돌렸습니다. 이 프로젝트는 Supabase 같은 외부 키 없이 정적 + `localStorage`로
도는 구조라 환경변수 없이 그대로 기동됩니다. 로그인 상태는 `localStorage`에 값을 시드해 재현했습니다. 캡처는
`review/images/2026-06-19/` 아래에 있습니다.

지난 8차에서 로그인 모달 캡처가 홈에서 트리거를 못 찾아 비어 있었는데, 이번엔 로그인 버튼이 서브페이지 Navbar에 있다는 점을 반영해
`/collections`에서 모달을 열도록 고쳤고, 로그인·회원가입·모바일 세 화면 모두 정상 캡처됐습니다.
