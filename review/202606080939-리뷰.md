## 전체 인상

지금 단계는 이제 막 `create-next-app`으로 프로젝트를 깔고, 화면을 본격적으로 그리기
직전입니다. 그래서 아직 대부분은 기본 템플릿 그대로지만, `layout.tsx`에는 손을 댄
흔적이 보입니다. `h-full`, `antialiased`, `min-h-full flex flex-col` 같은 클래스를
넣어 둔 걸 보면 "화면 전체 높이를 잡고, 세로로 쌓는 레이아웃을 만들겠다"는 의도가
이미 잡혀 있다고 봅니다. 디자이너 출신답게 레이아웃 뼈대를 먼저 잡으려는 감각이 좋습니다.

지금은 아직 "내 화면"이 들어오기 전 단계라, 이번 리뷰는 **본격적으로 Figma 디자인을
화면으로 옮기기 시작할 때 헷갈리지 않도록** 기초 몇 가지만 가볍게 짚어 줍니다.
무거운 백엔드 얘기는 하지 않습니다. 우리 목표는 디자인을 멋지게, 정확하게, 반응형으로
구현하는 것이라 생각합니다.

---

## 잘한 점

- **레이아웃 높이 사슬을 신경 썼습니다.** `html`에 `h-full`, `body`에 `min-h-full flex flex-col`을
  걸어 둔 부분입니다. 화면 전체를 꽉 채우는 레이아웃을 만들 때 이 "높이 물려주기"가 자주 빠져서
  `min-h-screen`을 억지로 쓰는 경우가 많은데, 정공법으로 잘 잡아 뒀습니다.
  (`page.tsx`에서 `flex-1`로 받아서 늘리는 것도 이 사슬과 잘 맞물립니다.)
- **`antialiased`로 폰트 렌더링까지 챙겼습니다.** 디자이너 출신다운 디테일입니다.
  글자 가장자리가 더 부드럽게 나옵니다.
- **다크 모드 클래스를 미리 깔아 뒀습니다.** 템플릿이 준 것이긴 하지만, `dark:` 변형을
  지우지 않고 둔 건 좋은 선택입니다. 나중에 다크 테마 디자인이 나오면 그대로 살릴 수 있습니다.

## 이렇게 해보면 좋아요

본격 작업 전에 정리해 두면 두고두고 편한 것들 위주로 골랐습니다.

### [필수] 페이지 메타데이터를 우리 프로젝트 것으로 바꿔주세요
`src/app/layout.tsx:15-18`

```tsx
export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};
```

브라우저 탭 제목과 검색/공유 시 보이는 설명이 아직 "Create Next App"입니다.
`package.json`에서는 이미 프로젝트 이름을 `project-carat`으로 바꿨는데, 정작
**사용자에게 보이는 제목은 기본값 그대로**라 살짝 아깝습니다. 서비스 이름과 한 줄 소개로
바꿔두면, 배포했을 때나 링크를 공유할 때 훨씬 그럴듯해 보입니다.

```tsx
export const metadata: Metadata = {
  title: "facet",                 // 또는 carat — 최종 서비스명으로
  description: "한 줄 서비스 소개를 적어주세요",
};
```

### [필수] `html lang="en"` → 한국어 서비스면 `lang="ko"`
`src/app/layout.tsx:27`

지금 `lang="en"`으로 되어 있습니다. 우리 서비스가 한국어 위주라면 `ko`로 바꿔주는 게
맞습니다. 이건 단순한 표시가 아니라 **스크린 리더가 어떤 언어로 읽어줄지**, 브라우저가
**번역 제안을 띄울지** 같은 동작에 직접 영향을 줍니다. 접근성 점수에도 잡히는 항목이라
습관처럼 챙겨두면 좋습니다.

```tsx
<html lang="ko" ... >
```

### [제안] `globals.css`의 `font-family`와 Tailwind 폰트 설정이 따로 놀아요
`src/app/globals.css:25` vs `src/app/layout.tsx:5-13`

`layout.tsx`에서는 Geist 폰트를 불러와 `--font-geist-sans` 변수로 연결해 두고,
`page.tsx`에서는 `font-sans` 클래스로 그 폰트를 쓰려고 합니다. 그런데
`globals.css`의 `body`에는 이렇게 적혀 있습니다.

```css
body {
  font-family: Arial, Helvetica, sans-serif;   /* ← 여기 */
}
```

이러면 **body 기본 글꼴은 Arial인데, `font-sans`를 건 요소만 Geist**가 되는, 섞인
상태가 됩니다. 디자인 일관성이 중요한 프로젝트에선 폰트가 들쭉날쭉해 보일 수
있습니다. 둘 중 하나로 통일하는 걸 권합니다.

- Geist로 통일하려면: `body`의 `font-family` 줄을 지우고, 대신 변수를 쓰거나
  `layout.tsx`의 `<body>`에 `font-sans` 클래스를 한 번만 걸어주면 됩니다.

```tsx
<body className="min-h-full flex flex-col font-sans">{children}</body>
```

이렇게 하면 `page.tsx`마다 `font-sans`를 또 안 붙여도 전체가 한 폰트로 통일됩니다.

### [제안] 색상은 직접 쓴 hex보다 디자인 토큰(테마 변수)으로
`src/app/page.tsx:39` 등

버튼 hover 색이 `hover:bg-[#383838]`, 테두리가 `border-black/[.08]`처럼 코드 안에
값이 박혀 있습니다. 템플릿이 준 거라 지금 당장 문제는 아니지만, 디자인을 본격적으로
옮기기 시작하면 **Figma의 색 토큰을 `globals.css`의 `@theme`에 한 번 정의해 두고**
`bg-primary`, `text-muted` 같은 이름으로 부르는 게 훨씬 관리하기 좋습니다.
색을 바꿀 일이 생겨도 한 곳만 고치면 전부 반영되기 때문이라 생각합니다. 이미 `--color-background`,
`--color-foreground`를 변수로 쓰고 있으니, 같은 방식으로 Figma 팔레트를 옮겨오면 됩니다.

### [사소] 본문 `<a>` 링크에 호버/포커스 표시가 없어요
`src/app/page.tsx:21-24, 28-31`

문단 안의 "Templates", "Learning" 링크는 색만 다르고 밑줄이나 hover 효과가 없어서
**클릭할 수 있다는 느낌이 약합니다.** 이건 템플릿 기본값이니 지금 고칠 필요는 없지만,
나중에 본인 화면을 만들 때 링크에는 `hover:underline`이나 색 변화를 줘서
"여기 누를 수 있다"는 걸 시각적으로 알려주면 좋습니다.

```tsx
<a className="font-medium text-zinc-950 hover:underline dark:text-zinc-50" ... >
```

## 화면 확인 (E2E)

이번엔 실제로 앱을 띄워서 첫 화면도 확인했습니다(`review/e2e/`에 리뷰용 Playwright, 캡처는 `review/images/`). 아직 백엔드가 필요 없는 단계라 환경변수 없이 그대로 떴습니다.

- 홈(`/`)은 정상 렌더됩니다. 다만 `images/01-home.png`처럼 **아직 create-next-app 기본 템플릿 화면**("To get started, edit the page.tsx file")이라, 본인 디자인이 들어오기 직전 상태인 게 그대로 보입니다.
- E2E로 페이지의 실제 값을 읽어 보니 **탭 제목이 `"Create Next App"`, `html lang="en"`** 으로 나왔습니다. 위 [필수] 두 가지(메타데이터·`lang`)가 화면/메타에서도 그대로 확인된 셈이라, 가장 먼저 손봐주면 좋겠습니다.

다음 리뷰 때 이 화면이 본인 Figma 디자인으로 바뀌어 있으면, 그때부터 마크업 구조·반응형을 같이 보겠습니다.

레이아웃 높이 사슬이나 `antialiased` 같은 디테일을 챙긴 걸 보니, 디자인을 화면으로

1분이면 끝나고, 한 번 해두면 끝나는 일입니다. 폰트 통일은 본인 화면을 그리기
직전에 같이 정리하면 딱 좋습니다.

다음 리뷰 때는 Figma에서 옮겨온 **진짜 화면**을 보고 싶네요. 그때부터가
진짜 재미있는 부분이라 생각합니다. 마크업 구조랑 반응형을 같이 봐줄게요. 천천히
그렇지만 꾸준히 갑시다. 화이팅입니다.
