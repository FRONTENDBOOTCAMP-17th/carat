# carat 코드 리뷰 (2026-06-24)

이번엔 리스트·상세 페이지 UI를 손보면서 `Breadcrumb`·`RelatedScroll` 컴포넌트를 새로 넣었고, 그 김에 제품 데이터 구조도 정비했네요. 디자인 완성도를 보는 프로젝트라 데스크톱과 모바일을 함께 띄워 새 화면 위주로 봤습니다. 스크린샷은 `review/images/2026-06-24/`에 있습니다.

---

## 1. 잘한 점부터

새로 들어온 두 컴포넌트의 완성도가 좋았습니다.

- **`Breadcrumb.tsx`** — `<nav aria-label="Breadcrumb">` + `<ol>` 구조에 마지막 항목은 `aria-current="page"`, 구분자 SVG엔 `aria-hidden="true"`까지 붙였네요. W3C 권고 패턴을 그대로 따른 덕에 스크린 리더에서도 현재 위치가 정확히 읽힙니다. 데스크톱은 Breadcrumb, 모바일은 BackButton으로 바꿔 주는 분기도 실제로 잘 동작했고요.
- **`RelatedScroll.tsx`** — `ResizeObserver`와 passive scroll 리스너를 쓰면서 정리(cleanup)까지 빠짐없이 해 둬서 메모리 누수가 없고, 비활성 버튼은 `tabIndex={-1}` + `aria-hidden`으로 처리해 키보드와 스크린 리더를 같이 챙겼습니다. 가장자리 그라데이션을 `opacity` 전환으로만 처리해 레이아웃 시프트가 없는 것도 좋았어요.
- **데이터 구조 정비** — `RawProduct`(JSON 입력)와 화면용 `Product`를 분리하고 카테고리 메타를 `CATEGORY_META` 상수 한 곳에 모아 둔 덕에, 카테고리를 추가할 때 한 군데만 고치면 됩니다.
- tsc와 build 모두 깨끗하게 통과합니다. 빌드 때 three.js `THREE.Clock` deprecation 경고가 하나 뜨긴 하는데, 라이브러리 쪽 문제라 동작엔 영향이 없습니다.

---

## 2. [필수] 모바일에서 리스트 제목이 화면 밖으로 넘칩니다

`/collections`와 `/fw-collections`를 390px 모바일에서 보면 가로 스크롤이 생깁니다. 측정해 보니 본문 폭이 358px인데 콘텐츠가 415px까지 밀려 **약 41px 넘칩니다**(`carat-02-list-mobile.png`).

원인은 리스트 헤더입니다.

```tsx
// collections/page.tsx (fw-collections도 동일)
<div className="flex items-end justify-between mb-8">
  <h1 className="text-5xl sm:text-6xl lg:text-7xl ...">COLLECTIONS</h1>
  <span className="... shrink-0 ml-6">12 PIECES</span>
</div>
```

Cinzel 폰트의 "COLLECTIONS"(48px)가 모바일에서 339px를 차지하는데, 여기에 `ml-6`(24px)와 "12 PIECES"(52px)가 `justify-between`으로 같은 줄에 붙다 보니 합이 컨테이너를 넘깁니다. "BEST PIECES"는 글자가 짧아 277px라 안 넘쳤고요. 그래서 제목이 긴 두 페이지에서만 터지는 겁니다.

긴 영어 카피를 큼직하게 쓰는 디자인 의도는 살리되 모바일에서만 안 넘치게 잡으면 되는데, 방법은 두 가지입니다. 모바일에서 폰트를 한 단계 줄이거나, 제목과 카운트를 세로로 쌓거나. 가이드에 코드로 정리해 둘게요.

## 3. [제안] / [사소] — 여유 있을 때

- **[제안] `RelatedScroll`의 스크롤 스텝**: `scroll-snap`(`x mandatory`)을 켜 뒀는데 버튼은 `scrollBy(±300)`으로 움직이네요. 카드 폭(`w-44` 176px)에 `gap-6`(24px)을 더하면 200px이라 한 번에 1.5칸씩 가 버려서 스냅이 살짝 어긋날 수 있어요. `scrollBy({ left: 200 })`처럼 카드 한 칸 단위로 맞춰 주면 스냅이 자연스러워집니다(`RelatedScroll.tsx:51`).
- **[제안] 상세 이미지에 `next/image`**: 상품 상세 이미지 영역이 지금은 플레이스홀더(`role="img"`)인데, 나중에 실제 이미지를 넣을 땐 `next/image`의 `fill` + `sizes`를 쓰세요. `<img>`로 직접 넣으면 LCP에서 손해를 봅니다(`products/[id]/page.tsx:63-66`).
- **[사소] `CategoryKey` 타입 중복**: `products/[id]/page.tsx:28`에서 `CategoryKey`를 지역으로 다시 선언했는데, 같은 타입이 `lib/products.ts`에 이미 있습니다. import해서 재사용하면 카테고리를 추가할 때 역시 한 군데만 고치면 되고요.
- **[사소] `RelatedScroll`이 가격을 안 내려줌**: `RawProduct`(id·name만)를 받아 `ProductCard`로 넘기다 보니 관련 상품 카드엔 가격이 안 보입니다. 의도된 디자인이면 그대로 둬도 괜찮고, 아니라면 `item.price`를 함께 전달하세요(`RelatedScroll.tsx:90` 부근).

## 4. 참고 — 데스크톱·상세는 깨끗합니다

상품 상세(`/products/...`)와 위시리스트는 390px에서도 가로 overflow가 0이었고, 데스크톱 리스트도 정상이었습니다. 이번에 넘친 건 제목이 긴 두 리스트 페이지뿐이라, 손볼 곳은 분명합니다.
