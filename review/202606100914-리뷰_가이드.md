# carat 3차 리뷰 — 해결 가이드 (2026-06-10)

리뷰에서 짚은 것들을 어떻게 고치는지 단계별로 적었습니다. 우선순위는
**반응형(필수) → 안 쓰는 컴포넌트 정리(제안) → 1차 미뤄둔 metadata/lang → 색·반복 정리** 순서를 권합니다.

---

## 1. [필수] 반응형 넣기 — 모바일 퍼스트로 생각하기

### 왜 깨졌나

Tailwind에서 `grid-cols-3`, `px-24`, `text-7xl`처럼 **접두사가 없는 클래스**는
**모든 화면폭에 무조건** 적용됩니다. 그래서 390px 모바일에서도 3열을 유지하려다 칸이 짜부라지고
글자가 겹칩니다.

해결 원리는 "**좁은 화면을 기본으로 두고, 넓어질 때만 늘린다**"는 모바일 퍼스트입니다.
Tailwind 접두사를 이렇게 읽으면 됩니다.

- 접두사 없음 = 모든 폭(= 모바일 기본)
- `md:` = 768px 이상
- `lg:` = 1024px 이상

즉 `grid-cols-1 md:grid-cols-2 lg:grid-cols-3`은 "모바일 1열, 태블릿 2열, 데스크톱 3열"입니다.

### 어디를 고치나 (파일별)

**`BestPieces.tsx`**
```tsx
// before
<section className="px-24 py-40">
  <h2 className="mb-16 text-6xl font-light">BEST PIECES</h2>
  <div className="grid grid-cols-3 gap-12">

// after
<section className="px-6 py-20 md:px-12 md:py-32 lg:px-24 lg:py-40">
  <h2 className="mb-10 text-4xl font-light md:mb-16 md:text-6xl">BEST PIECES</h2>
  <div className="grid grid-cols-1 gap-8 sm:grid-cols-2 lg:grid-cols-3 lg:gap-12">
```

**`Collections.tsx`** — 위와 동일한 패턴으로 `px`, `py`, 제목 `text`, `grid-cols`에 분기를 줍니다.

**`Footer.tsx`** — 4열은 모바일에서 2x2로 접는 게 자연스럽습니다.
```tsx
// before
<footer className="border-t border-zinc-200 px-24 py-20">
  <div className="grid grid-cols-4 gap-12">

// after
<footer className="border-t border-zinc-200 px-6 py-14 md:px-12 lg:px-24 lg:py-20">
  <div className="grid grid-cols-2 gap-10 md:grid-cols-4 lg:gap-12">
```

**`Hero.tsx`의 글자 크기** — `text-7xl`(PRISME)은 모바일에서 거의 화면에 꽉 차니
`text-5xl md:text-7xl` 정도로 줄여 주면 안전합니다. ESSENTIAL 블록의 `left-24`도
`left-6 md:left-24`로 바꾸면 모바일에서 왼쪽으로 붙지 않습니다.

### 확인하는 법

브라우저 개발자도구(F12) → 기기 툴바(Cmd+Shift+M) → 폭을 390 / 768 / 1280으로 바꿔 가며
글자가 안 겹치는지 봅니다. 또는 제가 만든 E2E를 그대로 돌려도 됩니다(아래 5번).

> Tip: 한 번에 다 고치려 하지 말고, **BestPieces 한 섹션만 먼저** 분기를 넣고 모바일에서 잘 접히는지
> 확인한 뒤, 같은 패턴을 Collections·Footer에 복사하는 식으로 가면 실수가 줄어듭니다.

## 2. [제안] 안 쓰는 `EssentialCollection.tsx` 정리

`page.tsx`가 import하지 않는 컴포넌트라 지금은 "유령 파일"입니다. 둘 중 하나로 정합니다.

**(A) 독립 섹션으로 쓰기** — 히어로 안의 ESSENTIAL 블록(`Hero.tsx` 181~208줄)을 빼서
이 컴포넌트로 옮기고, `page.tsx`에 끼웁니다.
```tsx
// page.tsx
import EssentialCollection from "@/components/EssentialCollection";
...
<Hero />
<EssentialCollection />
<BestPieces />
```
(이 경우 Hero 하단의 ESSENTIAL 블록은 지워 중복을 없앱니다.)

**(B) 안 쓸 거면 삭제** — `rm src/components/EssentialCollection.tsx`.

어느 쪽이든 "쓰는 컴포넌트만 남기는" 게 핵심입니다. 읽는 사람이 헷갈리지 않습니다.

## 3. [필수·1차] metadata와 lang — 한 줄씩

**`layout.tsx`**
```tsx
// before
export const metadata: Metadata = {
  title: "Create Next App",
  description: "Generated by create next app",
};

// after (예시 — 카피는 원하는 대로)
export const metadata: Metadata = {
  title: "PRISME — Jewelry Collection",
  description: "Contemporary jewelry shaped by balance, form and light.",
};
```
이건 브라우저 탭 제목, 구글 검색결과, SNS 공유 미리보기에 그대로 나오는 값이라 바꿔두면
바로 티가 납니다.

**`lang`** — 사이트 카피가 전부 영어라면 `lang="en"`이 **맞습니다. 그대로 두세요.**
나중에 한국어 UI가 섞이면 그때 `ko`로 바꾸면 됩니다. (스크린리더가 어떤 언어로 읽을지 결정하는 값이라
실제 콘텐츠 언어와 맞추는 게 원칙입니다.)

**`globals.css`의 폰트** — Geist를 불러놓고 body에서 Arial로 덮고 있습니다. 둘 중 하나로 통일합니다.
Geist를 쓸 거면 25줄을 지우거나 변수로 바꿉니다.
```css
/* before */
body { ...; font-family: Arial, Helvetica, sans-serif; }

/* after — @theme의 --font-sans(=Geist)를 따르게 */
body { background: var(--background); color: var(--foreground); }
```
(Tailwind v4 `@theme`에 이미 `--font-sans: var(--font-geist-sans)`가 있으니, body의
`font-family` 한 줄만 빼면 Geist가 적용됩니다.)

## 4. [제안] 반복되는 색·라벨 모으기

지금 당장은 안 해도 됩니다. 다만 같은 값이 여러 파일에 흩어져 있으면 디자인 변경 때 번거롭습니다.

**색 토큰** — `globals.css`
```css
@theme inline {
  --color-muted: #71717a;
  --color-subtle: #52525b;
}
```
그러면 `text-zinc-600` 대신 `text-subtle`처럼 의미가 드러나는 이름을 쓸 수 있습니다.

**반복 마크업** — 섹션마다 똑같이 나오는 라벨/제목을 작은 컴포넌트로 빼면 한 곳에서 관리됩니다.
```tsx
// SectionLabel.tsx
export default function SectionLabel({ children }: { children: React.ReactNode }) {
  return <p className="mb-4 text-sm tracking-[0.4em]">{children}</p>;
}
```
