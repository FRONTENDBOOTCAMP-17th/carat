# carat 해결 가이드 (2026-07-07)

이번엔 급히 고쳐야 할 게 거의 없어서, 리뷰에서 짚은 두 가지를 어떻게 다듬는지와, 발표 데모에서 3D가 안 뜰 때 무엇을 대비해두면 되는지만 예시와 함께 정리합니다. 순서는 발표에 중요한 것부터 두었습니다.

## 1. 발표 데모에서 3D가 안 뜰 때 대비 (가장 중요)

3D는 발표장 환경(네트워크, 프로젝터 GPU, 브라우저)에 따라 가장 잘 흔들리는 부분이라, 안 뜰 경우를 미리 막아두는 게 실전에서 제일 값집니다.

### (1) 로컬 프로덕션 백업을 미리 띄워둔다

배포본이 느리거나 안 뜰 때를 대비해, 발표 노트북에서 프로덕션 빌드를 미리 돌려두세요.

```bash
npm run build
npm run start   # 기본 http://localhost:3000
```

프로덕션 빌드는 dev 서버(`npm run dev`)보다 3D 초기 로딩이 빠른 데다 실제 배포본과 같은 조건이라, 데모용으로는 이쪽이 더 안전합니다. 발표 직전에 한 번 미리 켜서 히어로와 Essential 뷰어가 잘 도는지만 확인해두세요.

### (2) 폴백·정지 화면을 스크린샷으로 확보한다

이미 `canRenderRingScene()`로 WebGL 미지원·Gecko/Android 폴백을 만들어 뒀으니, 최악의 경우 정지 화면으로라도 설명할 수 있게 캡처를 준비하세요. 크롬 개발자도구에서 WebGL을 잠깐 끄고(혹은 `about:gpu`류로 확인) 폴백이 어떻게 보이는지 한 장, 그리고 데스크탑에서 3D가 정상으로 도는 장면 한 장을 슬라이드에 넣어두면 됩니다.

### (3) 발표 직전 시크릿 창 워크스루

```
project-carat.vercel.app 을 시크릿(비로그인) 창으로 열기
→ 홈(히어로 3D) → Essential(IRIS 3D, 스와치 3색 눌러보기)
→ 검색(ring 검색) → 상세 → 위시리스트
```

캐시가 없는 첫 방문에서 로딩과 3D 렌더가 어떻게 보이는지, 그게 곧 심사자가 마주하는 화면입니다. 여기서 눈에 걸리는 게 있으면 그것만 손보면 됩니다.

## 2. [제안] WebGL 판정의 하이드레이션 다듬기

지금 코드는 이렇습니다.

```tsx
// EssentialRingViewer.tsx / Hero.tsx
const hasWebGL = useMemo(() => canRenderRingScene(), []);
```

`canRenderRingScene()`는 서버(window 없음)에서 `true`를 주도록 돼 있어서, 서버는 `<Canvas>`를 그리는데 모바일 파이어폭스처럼 클라이언트에서 `false`가 나오는 환경에서는 그 자리를 폴백 `<div>`로 바꿔 그리게 됩니다. 이렇게 서버는 A, 클라이언트는 B로 첫 렌더가 갈리는 게 하이드레이션 불일치인데요, 실제로 걸리는 브라우저가 극소수라 당장 급하진 않습니다. 다듬는다면 클라이언트에서 마운트된 뒤에만 판정하도록 바꾸면 됩니다.

```tsx
const [ready, setReady] = useState(false);
const [hasWebGL, setHasWebGL] = useState(false);

useEffect(() => {
  setHasWebGL(canRenderRingScene());
  setReady(true);
}, []);

// 렌더
if (!ready) {
  // 서버·클라이언트 첫 렌더가 동일 — 폴백(또는 빈 stage)만 그림
  return (
    <div
      className="absolute inset-0 transition-colors duration-700"
      style={{ backgroundColor: fallbackTint }}
      aria-hidden="true"
    />
  );
}
return hasWebGL ? (/* <Canvas> ... */) : (/* 폴백 div */);
```

이렇게 하면 서버와 클라이언트의 첫 렌더가 똑같이 폴백이 되니 불일치가 사라지고, 마운트된 다음에야 3D로 올라갑니다. 3D는 어차피 클라이언트에서만 도는 거라 체감 차이는 없으면서 콘솔 경고만 깔끔해집니다. Hero와 Essential 뷰어 둘 다 같은 패턴이라 한 군데를 고치면 다른 쪽도 똑같이 적용하면 됩니다.

## 3. [사소] 히어로 첫 프레임 서브카피 대비

밝은 다이아몬드 위에 회색 서브카피가 얹히는 순간의 대비만 살짝 올리는 정도입니다. 의도한 레이어링이면 그대로 둬도 괜찮습니다. 손댄다면 서브카피 한 줄에만 미세한 그림자나 색 계층 한 단계를 주면 됩니다.

```tsx
// 예: 서브카피에 아주 옅은 텍스트 섀도로 밝은 배경에서도 읽히게
<p className="... text-content-secondary [text-shadow:0_1px_2px_rgba(0,0,0,0.15)]">
  {t.hero.subcopy}
</p>
```

또는 역할 토큰을 한 단계 진한 쪽(`text-content-secondary` → `text-content-primary`)으로만 바꿔도 됩니다. 프로젝터 밝기가 뜨는 발표장을 생각하면 이 한 줄이 더 또렷하게 읽히는 편이 안전합니다.
