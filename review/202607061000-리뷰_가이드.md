# carat 마무리 가이드 (2026-07-06) — 남은 이틀, 이 순서대로

발표까지 이틀입니다. carat은 백엔드 의존이 없어 배포가 쉽고, 강점이 "잘 만든 화면"에 있으니 그걸 보이게 만드는 데 집중하면 됩니다. 아래 순서대로 하나씩 해보세요.

## 1. Vercel 배포 (오늘, 30분이면 됩니다)

정적 위주라 환경변수 설정 없이도 대부분 그대로 올라갑니다.

1. https://vercel.com 에 GitHub으로 로그인 → New Project → carat 레포 선택.
2. Framework는 Next.js로 자동 인식됩니다. 빌드 명령·출력 디렉터리는 기본값 그대로 두세요.
3. Deploy를 누르고, 끝나면 나오는 주소(`carat-xxxx.vercel.app`)를 복사해 둡니다.
4. **시크릿 창으로** 그 주소를 열어 메인부터 제품 상세·검색까지 한 바퀴 걸어보며 깨진 이미지나 404가 없는지 확인하세요. 로컬에서만 되던 경로가 배포본에서 막히는 경우가 있으니, 반드시 배포본에서 확인합니다.

배포가 끝나면 README 맨 위에 링크를 답니다.

```markdown
## 🔗 라이브 데모
👉 **https://carat-xxxx.vercel.app**
```

## 2. 히어로 GIF 한 장 (오늘)

레포를 여는 사람은 코드를 읽기 전에 화면을 먼저 보고 싶어 합니다. carat의 Hero(r3f)나 대표 제품 화면을 짧은 GIF로 만들어 README 맨 위에 넣으세요.

- 화면 녹화: macOS면 `Cmd+Shift+5`로 영역 녹화 → mov 저장.
- GIF 변환: [ezgif.com](https://ezgif.com/video-to-gif) 같은 무료 도구에 mov를 올리면 GIF로 바꿔줍니다. 5~8초, 폭 800px 정도면 충분합니다.
- README 삽입:

```markdown
![carat 데모](./docs/demo.gif)
```

움직이는 화면 한 장이 설명 문단 열 개보다 강합니다. 디자이너 출신이라는 게 여기서 가장 잘 드러납니다.

## 3. eslint 8건 정리 (내일)

```bash
npx eslint .
```

대부분 `react-hooks/set-state-in-effect`입니다. 두 가지 길이 있어요.

- **정리하는 경우**: effect 안에서 `setState`를 바로 부르는 대신, 파생 값이면 렌더 중에 계산하거나 `useMemo`로 빼고, 정말 이펙트가 필요하면 의존성 배열을 정확히 채웁니다.
- **의도한 패턴인 경우**: 왜 이 자리에서 필요한지 한 줄 주석으로 남기거나, 해당 줄만 `// eslint-disable-next-line react-hooks/set-state-in-effect` 로 사유와 함께 예외 처리합니다. 무작정 끄는 것과, 이유를 적어두고 끄는 것은 레포를 보는 사람에게 인상이 완전히 다릅니다.

목표는 `npx eslint .`가 깨끗하게 끝나는 상태입니다.
